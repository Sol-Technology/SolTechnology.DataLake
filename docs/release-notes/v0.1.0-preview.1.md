First preview of SolTechnology.DataLake: a folder of Parquet or Avro files, on local disk, S3 or Azure, read as one table into your own classes. No Spark, no JVM. Iceberg tables come in 0.3.

```
dotnet add package SolTechnology.DataLake --prerelease
dotnet add package SolTechnology.DataLake.Aws --prerelease
dotnet add package SolTechnology.DataLake.Azure --prerelease
dotnet tool install -g SolTechnology.DataLake.Cli --prerelease
```

```csharp
var orders = DataLake.Open<Order>("s3://shop/orders/", new DataLakeOptions { Storage = new S3Storage(new AmazonS3Client()) })
    .Where(o => o.Date == yesterday && o.Country == "PL");

await foreach (var order in orders.ReadAsync()) { }
```

What's in it:
- Hive partitions from the path fill properties, typed as the property
- LINQ filters skip files by partition and row groups by min/max statistics. One day out of 30 reads 33x faster than Parquet.Net file by file, with 85x less memory
- Structs, lists and maps into nested classes, lists and dictionaries
- Timestamps through SolTechnology.DateTimeZone: UTC instants into `DateTimeZone`, timestamps without a zone into `UnzonedDateTime`
- Clear errors instead of guesses: a missing column, a null in a non-nullable property, a lossy conversion, a corrupt file (with its name and column)
- Files from Spark, parquet-mr, Impala, Hive, pyarrow, DuckDB and protobuf writers, older list layouts included. 92 of 114 files from apache/parquet-testing and the Parquet.Net test data read exactly like pyarrow reads them. pyarrow can't read 6 others; 16 fail inside Parquet.Net
- Avro files with the same mapping rules
- S3 and S3-compatible storage, Azure Blob Storage, ADLS Gen2 and OneLake, all with ranged reads
- `datalake ls`, `schema`, `head`
- `datalake.scan` activity and counters for OpenTelemetry

Not yet: writes (0.2), Iceberg tables (0.3, 1.0), Delta Lake.
