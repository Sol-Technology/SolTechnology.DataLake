Second preview of SolTechnology.DataLake: writes, and Apache Arrow into your classes. Iceberg tables come in 0.3.

```
dotnet add package SolTechnology.DataLake --prerelease
dotnet add package SolTechnology.DataLake.Aws --prerelease
dotnet add package SolTechnology.DataLake.Azure --prerelease
dotnet add package SolTechnology.DataLake.Arrow --prerelease
dotnet add package SolTechnology.DataLake.Avro --prerelease
dotnet tool install -g SolTechnology.DataLake.Cli --prerelease
```

Packages, all MIT:

| Package | What is inside |
|---|---|
| SolTechnology.DataLake | `LakeContext`, `IDataset<T>`, Parquet, `UseFiles`, `UseInMemory`, `Dataset.Open`, local disk and memory |
| SolTechnology.DataLake.Aws | `S3Storage` |
| SolTechnology.DataLake.Azure | `AzureBlobStorage` |
| SolTechnology.DataLake.Arrow | `ArrowConvert`, Arrow IPC files in datasets with `f.Arrow()` |
| SolTechnology.DataLake.Avro | Avro files in datasets with `f.Avro()`; uses AvroConvert, which has its own licence |
| SolTechnology.DataLake.Cli | the `datalake` tool, every format |

```csharp
public class ShopLake(LakeContextOptions<ShopLake> options) : LakeContext(options), IShopLake
{
    public IDataset<Order> Orders => Dataset<Order>("orders");
    protected override void OnModelCreating(LakeModelBuilder model) => model.Dataset<Order>("orders").PartitionBy(o => o.Date, o => o.Country);
}

services.AddDataLake<IShopLake, ShopLake>(o => o.UseFiles("s3://shop/", new S3Storage(s3), f => f.Avro()));   // tests: o.UseInMemory()

await lake.Orders.ReplacePartitionsAsync(todaysOrders);

var result = await statement.ExecuteQueryAsync();          // ADBC: Databricks SQL, Snowflake, Flight SQL
await foreach (var trip in ArrowConvert.DeserializeAsync<Trip>(result.Stream!)) { }
```

What's new:
- `LakeContext`: one API for every storage technology, like EF Core's `DbContext` without change tracking. Datasets declared in `OnModelCreating`, the provider chosen at registration (`AddDataLake<TContext>`), so swapping folders of files for Iceberg (0.3) does not touch the code that reads and writes. `IDataLake` and `IDataset<T>` to mock; `UseInMemory()` runs the real files provider on memory for tests
- `UseFiles(root, storage, f => ...)`: a folder of files per dataset, hive partitions, no transactions. Writes are Parquet; Avro and Arrow IPC are read with `f.Avro()` and `f.Arrow()` from their own packages. A `.avro` or `.arrow` file without its format added is an error that names the package to add, not a skipped file
- Writes with the words data engineers know: `AppendAsync`, `OverwriteAsync` (the whole dataset), `OverwriteAsync(rows, where)`, `ReplacePartitionsAsync` (dynamic partition overwrite), `DeleteAsync(where)`. Only declared datasets can be written, folders partitioned differently stop a write, a failed write removes its files
- Parquet files from your classes: hive partitions, Snappy, Zstd or Gzip, row group and file size. What a write writes, a read reads back into the same class
- Types other engines read as what they are: timestamps in microseconds with or without UTC, decimals with the precision you set (never rounded), UUID, time of day, enums by name, structs, lists and maps. DuckDB and pyarrow read the files in CI
- Correct timestamp statistics: Parquet.Net 6.1 writes min/max of microsecond timestamps in milliseconds, so DuckDB and Spark would skip matching rows. DataLake fixes them in every file it writes
- Storage writes: write, write only if absent (one winner between concurrent writers), delete, on local disk, S3 (multipart for large files) and Azure
- `ArrowConvert`: record batches, `IArrowArrayStream` (ADBC results) and Arrow IPC files and streams into classes and back. Samples for Databricks SQL, Snowflake and Flight SQL
- Arrow IPC files (`.arrow`, `.feather`, `.ipc`, `.arrows`) in datasets
- Nested columns 2x faster with half the memory: 200 000 orders with lines in 303 ms, on par with Parquet.Net's own serializer
- Filters skip row groups by text statistics too (ASCII values)
- Documentation per provider: [Files](../providers/Files.md), [InMemory](../providers/InMemory.md)
- `datalake cat` (JSON lines or CSV) and `datalake stats` (rows, row groups, partitions, nulls and min / max per column)
- Benchmark against pyarrow.dataset on the same files: 5x faster when every row becomes an object

Changed since 0.1:
- `DataLake.Open<T>` is now `Dataset.Open<T>`, read-only, for a quick look at one folder; writes go through a context. Avro and Arrow files need their format in `new DataLakeOptions { Files = f => f.Avro() }`
- `ILakeStorage` has `WriteAsync` and `DeleteAsync`, with default implementations that throw `NotSupportedException`, so your own read-only storage still compiles
- Avro and Arrow moved out of the main package into SolTechnology.DataLake.Avro and SolTechnology.DataLake.Arrow; `ArrowConvert` keeps its namespace, `SolTechnology.DataLake.Arrow`
- Licence: MIT for every package. SolTechnology.DataLake.Avro uses AvroConvert, which has its own licence and prints its notice when no AvroConvert licence is declared
